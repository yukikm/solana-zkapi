[既存 native tests](../services/challenger/src/tests.rs) の `native_daemon_prove_sign_persist_send_restart_and_stale_root_recovery` は normal、lose-once、stale-once、restart、confirmed、expired-upload、buffer-expired、upload-rejected の 8 ケースを実行する。新しい real tree proof、実 SDK の signed v0、送信前 fsync journal、失敗後の buffer cleanup/reproof を検査する。`rpc_daemon_replays_durable_history_and_reconciles_restart_forks_and_cuts` は actual SBF archive の durable replay と fork/rollback/account-cut 拒否を検査する。`alert_transitions_survive_restart_and_spool_delivery_is_idempotent` は 60 秒/5 分/期限前の alert 分類と spool 再配送を検査する。

[I09 runner](../scripts/run_i09_challenger.py) は独立 OS process の `challengerd once/recover` でも同じ journal を再開し、実署名済み execute を confirmed の間維持し、fee key 削除後に finalized 復旧する。別の [SBF runner](../tests/svm/src/bin/challenger.rs) は実 Vault で deposit A→deposit B→escape A→historical RP/current tree challenge、pause/deadline、実 SDK 署名を実行する。RPC daemon の synthetic outcome と SBF の token/root 結果を一つの公開 cluster 実行として合算しない。

I10 の [追加 test](../services/challenger/tests/i10_acceptance.rs) `repeated_status_outages_and_process_restarts_preserve_unknown_execute` は、この基盤を使って 1 real-proof job を Unknown Execute まで進める。fee key を削除し、status HTTP 503 を 8 回、confirmed-only を 8 回、各回を新しい `challengerd recover` process で復旧する。署名・bytes・payload・evidence の不変、追加送信 0、page event の重複 0、最後の finalized 復旧を検査する。alert の発火は discovery time を 301 秒古くするため、実時間 5 分停止や production SLO の試験ではない。report は `target/i09-challenger/i10-restart-results.json`。

多数の distinct Pending/nullifier を同時処理する prover queue capacity と large archive の容量・長時間 soak は、この 1-job 試験の対象外。仕様に数値 workload がないため未知の production capacity を合格にしないが、同じ 1 本の実 RP を異なる N の job に複製して負荷成功と数えることもしない。実負荷目標を定める場合は valid distinct RP/Pending と保存容量を伴う別の容量測定として記録する。
