Follow-up: the [implementation review](I10-single-deposit-review.md) fixes legacy

## Implementation

- `zkapi-layout2` strictly expands 436 compact bytes to the existing 692-byte
  deposit. The eleven public inputs, proof, VK and account layout stay unchanged.
- The Vault authenticates its PoolConfig and owner signer before expansion, then
  calls the existing financial handler. Its strict entrypoint accepts exactly
  444 instruction bytes. The published IDL is generated by the Anchor compiler.
- Indexer replay expands compact instructions using the verified Pool binding,
  supporting mixed historical buffer/inline instructions and absent event logs.
- The SDK selects compact deposits only through an authenticated manifest plus
  independent build capability pin. IDL argument/account mismatches fail before
  signing. Control/challenger manifest parsing retains mandatory buffer support.
- `WalletClient` keeps a distinct inline plan and schema 2 journal in the same
  encrypted storage. Exact signatures are durable before sending. Unknown
  financial sends cannot become another deposit or automatically fall back to
  buffers. Schema 1 and saved buffer operations retain their original behavior.
- Browser and native clientd both use this SDK. Install a rebuilt distribution
  and new independently authenticated build/IDL pins before enabling compact
  deposits; a server capability alone cannot switch an existing client.

## Deployment boundary

Enable `v0_inline_deposit_v1` only in a new authenticated manifest whose
`idl_hash` and program/build artifact hashes match the new build. The installed
SDK trust policy must explicitly include
`build.transactionFormats: ['v0_buffer', 'v0_inline_deposit_v1']`.
The cryptographic circuit profile stays unchanged. Do not overwrite the trust
pins on a funded or unresolved journal. The first public canary requires an
isolated devnet program/pool and a new journal, followed by independent receipt
and balance collection and an actual Phantom signature-count check.

Local SBF/SDK/browser fixtures are not public cluster or real wallet acceptance.

## Reproduction

Run `python3 scripts/run_single_deposit_acceptance.py` from the repository with
the already installed pinned toolchains/dependencies and legacy wrong-VK fixture.
`ZKAPI_NODE`, `ZKAPI_SBF` and `ZKAPI_SCHEMA_PYTHON` select installed executables.
The runner uses isolated local outputs, retains failed reports, and does not
load live credentials, deploy, migrate journals or send public transactions.
The CI transport job also runs the compact SDK/SBF and indexer replay cases;
hosted CI was not executed in this task.
