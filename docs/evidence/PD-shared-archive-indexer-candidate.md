# Shared archive indexer: local candidate

Recorded 2026-10-08 JST from observations on 2026-10-07 UTC. The opt-in `challengerd archive-indexer` mode supplies the public indexer with the challenger's already committed, decoded `FinalizedBlock` evidence. It removes the indexer's second full-block RPC scan while retaining original-start replay and independent finalized account reconciliation. The [machine-readable report](PD-shared-archive-indexer-candidate.json) pins this local candidate. The [disk-backed reader candidate](PD-challenger-disk-reader-candidate.md) and [actual reader runtime observation](PD-challenger-reader-runtime-observation.md) are earlier, separate scopes.

The source is an existing v2 archive. The follower opens one fixed head inode, checks the state checksum and Pool, verifies all referenced chunks and the complete original legacy prefix, then exposes bounded borrowed blocks. It does not acquire a writer lock, write source files or health, migrate, adopt or delete orphans, open a DB, load fee material, or construct the financial challenger runtime. The existing journal format and writer behavior are unchanged. The new process writes only its separate public indexer snapshots; canonical source/output overlap is rejected.

Incremental refresh requires the exact previous tail reference and unchanged Pool/legacy identity, verifies every new chunk and parent/count link, then installs the complete extension atomically in memory. Previously authenticated files use trusted Unix device/inode/size/mtime/ctime continuity rather than rereading the entire legacy archive every poll. Missing or changed files fail closed. Every replayed chunk is hashed again before callbacks. This boundary assumes the ordinary immutable writer and trusted local filesystem; it does not protect against privileged metadata forgery. Payload memory is one original chunk, including the pre-existing oversized-single-block exception. Reference and indexer digest metadata still grow.

The original `start_slot` is retained. The consumer holds its finalized target and captured account cut while waiting, replays only through that exact cut, and verifies the independent accounts and block anchor before publishing. A cut older than 30 seconds is recaptured; source errors latch readiness unavailable. There is no `getBlocks` or full-transaction `getBlock` fallback in this mode. These stored blocks cannot reproduce the original RPC JSON, and no such reconstruction is performed. Cold validation precedes the HTTP listener and Ctrl-C handler; default signal termination during cold open is not a graceful cancellation claim.
