# I07 — native proxy/provider adapters

2026-10-04 JST。**OpenAI Chat Completions/Responses、Anthropic Messages/count_tokens、OpenRouter Chatのlocal adapter実装**。共有control ledgerの予約・immutable attempt・最終claim・署名receiptへ接続し、provider固有の入力検査、HTTP、SSE、usage正規化を実装した。実provider credential、実請求照合、公開RPC/wallet、hosted CI、G1〜G4は未検証。local fixtureの成功を実provider受入に読み替えない。

## 成果物と境界

- [proxy module](../../services/control/src/proxy/mod.rs)：profile、native endpoint、機能・料金表の結合。
- [request validation](../../services/control/src/proxy/request.rs)：1 MiB・重複JSON key・UTF-8検査、text/client function/tool call履歴、明示output上限、context最大値による整数予約。未知field、multimodal、hosted tools、任意provider routing、保存済みresponse参照を送信前拒否。Responsesは`store=false`と`background=false`を固定。
- [HTTP transport](../../services/control/src/proxy/transport.rs)：公式provider hostnameだけを選択し、起動時の公開DNS addressをpin。system proxy・redirect・reqwestのprotocol retryも禁止。運営credentialから必要headerのみ構築する。local fixtureのoverrideは明示test設定でnumeric loopbackのHTTP originだけ。
- [usage/SSE](../../services/control/src/proxy/usage.rs)：inclusive inputからcacheを差し引き、Anthropic exclusive inputへcacheを足し戻さず、5m/1hを分離。reasoningはoutputに内包。累積deltaは加算しない。usage欠落・未知料金項目・矛盾counter・不完全streamはunknown。
- [adapter tests](../../services/control/tests/proxy_adapters.rs)と[固定contract snapshot/fixture](../fixtures/i07-provider-contracts.json)。snapshotは2026-10-04に確認した一次資料から選んだschema契約と**合成fixture**であり、実provider応答の保存ではない。

初期設計の`services/proxy/`に別ledgerを作らず、`services/control/src/proxy/`にadapterを置く。本文はこのmoduleの一時メモリーとHTTP転送で扱い、control ledgerにはkeyed HMAC、provider request ID、usage、料金計算と署名明細だけを渡す。この配置差は単一writer/dispatch ownershipを維持するため。元回路・hash・Vault・I04 transportは変更しない。固定upstreamとlicenseは保持する。

## 現時点の制限

モデル・context最大値・output最大値・cache profile・有効な整数料金表はdeploymentが明示設定する。未確認の実モデル名/価格を自動公開しない。OpenAIの新しいcache-write料金と従来cache-readのみのmodelは別profileにし、料金項目が一致しなければ起動/受付を拒否する。標準text/function subset以外の未知parameterは明示エラーになる。特定CLIやClaude Code全機能の互換性は未検証。

600秒のhard deadlineは送信とbody読取を含む。stream途中のprovider errorは完成frame単位で検出し、生error本文を中継しない。配送queueが満杯なら250 msだけ待ち、taskの一時的な実行順序による欠落を避ける。それでも遅いclientなら配送を打ち切ってdrainし、最終usageを読む。呼出元が保持する独立taskの終了後のみattemptをfinishedにできる。process喪失や旧ownerの生存時には、DB flagだけでfence扱いにしない。

`lookup_usage`はこの固定text/cache契約を完全に再構成できるnative照会を実証していないためunavailable、`cancel`は課金停止を確認できないためfalseを返す。推論の再送や推測請求はしない。OpenRouterのgeneration照会の存在は確認済みだが、全cache料金区分を確定するlive検証は未実施。完了したownerのunknownは共有ledgerのwaiver方針で運営負担にし、live keyを配るdirectへ流用しない。

参考一次資料と採用schemaの差は[contract snapshot](../fixtures/i07-provider-contracts.json)に記録。OpenRouterはusageを常時返す現行契約であり、互換用の`stream_options.include_usage=true`に依存しない。実providerの公開受入・本番egress/failover・外部請求との照合・全面的なprivacy scanは後続gateである。
