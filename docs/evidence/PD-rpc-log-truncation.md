# RPC log truncation decoder correction

A valid finalized Devnet block stopped archive catch-up because the decoder treated logs after Solana's truncation marker as a continuous invocation trace. The eight-line correction stops **log evidence** at the exact bare `Log truncated` marker while retaining every transaction and compiled instruction. Journal formats, retained history and public client artifacts are unchanged.

At the 2026-10-08 02:39:44 UTC observation, the archive retained 94,459 blocks through slot 508615469. Reclassification of that same retained ten-minute log window found 264 `RPC archive encoding` errors and 297 follower reconciliation-unavailable messages. No numeric RPC failure diagnostic matched that window; this is not a general claim about transport availability. Admission was disabled, with zero pending challenger jobs and unknown signatures.

A bounded read obtained the next produced block, slot 508615470, with parent 508615469 and nine transactions. Its exact 61,307-byte response is retained as the public regression fixture (SHA-256 `1cb64ee1a19f96a52356488312e3a563f673b328ff1b57f2e252bb160f109b1c`). The native decoder before the fix rejected the complete block and transaction index 2 with `Vault invocation success cannot be established`. That transaction has 128 logs: the marker at index 126 is followed by one shorter success line. The corrected native decoder accepts the same complete block and all nine transactions individually. Diagnostic log removal helped isolate the failure and was not used as the acceptance input.

Agave v2.3.13's collector emits the marker on the first oversized log without consuming that rejected line's byte allowance; a later shorter line can still fit. Parsing those later lines as a complete stack is therefore unsound. Program-generated text has a separate `Program log: ` prefix. See the [official log collector](https://github.com/anza-xyz/agave/blob/v2.3.13/log-collector/src/lib.rs#L23-L37) and [stable program logging](https://github.com/anza-xyz/agave/blob/v2.3.13/program-runtime/src/stable_log.rs#L30-L40).

Evidence before the marker remains subject to the existing strict ownership and completion rules. Unknown inner invocations and unknown ancestors remain unknown and cannot authorize Vault replay; known failed ancestors remain failed. A program-prefixed imitation cannot trigger the boundary. Existing successful outer-transaction and optional-event semantics remain unchanged. The fix does not skip a block or infer missing CPI success.

Pinned Rust 1.90.0 validation passed all **19 replay tests**, zero failures or ignored tests, plus the indexer formatter and offline, locked, all-target Clippy with warnings denied. The regressions cover the exact saved block, unknown and failed ancestors, pre-marker evidence ownership, post-marker evidence exclusion, and malformed pre-marker traces. The coordinator and an independent peer reviewed the source and reported no blocking finding; the peer did not rerun the tests.

A separate network-disabled, offline Linux build passed from 184 frozen inputs (manifest SHA-256 `2a64f42f3346cfbdd6c9a7b2f5691ffc88fe2e6607dc958fc6b65c231c299c99`). It overlays only the decoder change and regression files onto the prior writer snapshot. The resulting 11,669,872-byte binary is `3893ca8fe2bbdb1275e6d8faea24a918f24192ccd7daa584b6baa8a28a4df2d8`; read-only, network-disabled smoke returned the expected no-config exit 2 and maximum GLIBC requirement 2.34. All 184 copied inputs and the binary hash were independently rechecked.

The original decoder failure, initial isolated-manifest path error, initial test-formatting failure and first Linux Rustup lookup failure remain retained. The corrected Linux invocation explicitly selected the installed toolchain and succeeded without network access. Exact source, result and log hashes are in [the companion record](PD-rpc-log-truncation.json).

The writer was stopped at 02:48:10 UTC, the reviewed binary was installed at 02:55:10 UTC, and its new process was observed running at 02:59:38 UTC. The stop cut shows an inactive unit, an empty cgroup and systemd result `success`; native exit metadata had been cleared, so **native exit 0 is unknown**. The old binary was retained. Installation preserved the exact journal head, all 486 immutable archive entries (485 chunks plus the legacy backup), owner lock, legacy identity, financial/database cut and configuration. The same follower and other service processes remained in place.
