固定環境：cargo-build-sbf 4.1.0、platform-tools v1.54、SBF **v0**、LiteSVM 0.6.1 / Agave 2.2.0、bundled SPL Token 3.5.0。native processor登録や診断用予算引上げを使わず、全transactionにComputeBudget 1,000,000 CUを指定した。次表はComputeBudget命令を含むtransaction実消費。

| 経路 | CU min–max | buffer execute v0全体 | 同じ測定accountsでinline化した場合 |
|---|---:|---:|---:|
| deposit | 153,774–154,938 | 516 bytes | 1,177 bytes |
| mutual_close | 316,612–317,443 | 516 bytes | 1,797 bytes、上限超過 |
| initiate_escape | 300,186–301,033 | 516 bytes | 1,797 bytes、上限超過 |

257ケース全体でも最大317,443 CU。失敗ケースも100万CU未満で所定のエラーとなり、CU枯渇を拒否成功と数えない。全送信はv0＋1署名＋実accounts＋ComputeBudgetをserializeして1232 bytes以内。inline欄は**測定用account listでのサイズ参考値**であり、productionのinline対応をadvertiseする根拠にしない。

研究harnessの約37〜67万CUから、採用版ではcanonical Fr判定・public input比較を32-byte BEの比較で行い、不要なArkworks Frへの変換/再encodeを省いた。Poseidonを別hashへ変えていない。tree tagの制約は同じ回路に残り、SBFで重複計算しない。

native releaseでのtree生成15件は1,379〜2,792 ms（他のhost検証も動いた共有環境）。prepare済みwitnessから、制約確認・prove・local verifyを含むfixture生成時の値であり、PK取得/deserialize・browser・送信・root競合の時間は含まない。CLIの別OsRng生成proofもSBFで受理した。5分challenge運用目標の最終判定はI08/I09に残る。

## 拒否・原子性の確認

- 全11 tree inputs、元request 12 / withdrawal 14 inputs、Fr/Fq非canonical、proof各座標、A符号、G2係数順、曲線上だが正しい部分群にないG2点、各点の無限遠、別compile VKを拒否。ホスト側では11 public inputs・32 siblings・u32/u64/op境界の47 invalid witnessesを拒否した。
- 同一Vault・同一rootの別Note WP、同一Note・別root WP、別Vault WP、別Pending NのRP、別Vault RP、別tree opを拒否。proofのbyte破損だけによる試験ではない。
- 過去RP.rootがcurrent rootとPending.old_rootの**両方と異なる**challengeを成功させた。pause中でもchallenge/expiryを許可し、Clock境界を確認した。
- escape→challenge→同じNでescape再試行を実行し、Nの再利用を拒否。Note/root/C/D/expiry、config keys/genesis、実destination token owner、profile/layout/backend/policyの不一致を拒否した。
- sourceを測定Vault PDA所有にして`invoke_signed`のToken TransferCheckedを実行。転送額は検証済みD/Bから求めた。2回目のtreasury CPIを凍結accountで失敗させ、1回目CPI成功のログと2件のinner instructionを確認したうえで、pool snapshot・source/destination/treasury残高・bufferを**全byte rollback**として検査した。sequence、root、Note status、Nも含む。
- sealed payloadのpool/uploader/digest/期限/owner、署名対象expected_digest、layout長、public/proof逆順、余分な末尾を拒否した。buffer upload lifecycleの代替試験ではない。
- test profileのproduction指定、既知test PK/VKをceremony済みへ偽装したprofile、誤署名/誤trusted key/異なるpool・program profileを拒否。CLIで改変PK、誤trusted profile hash、誤path、productionへのtest指定を拒否した。

empty root `2bb43759c24665d98a33afa8d5094817d359d5e4c72a45b45a2a563176d37933` は元Rustのz32と、固定upstreamのSolidity PoseidonをEVMで32回計算した値が一致する。Foundry 1.3.1 / solc 0.8.28、test 1件PASS。空tree初期化でSBF Poseidonを32段計算する必要はない。
