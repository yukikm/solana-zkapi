# I04 buffer・SDK transaction・indexer

2026-10-04 JST。開始点は `03866a48fd0bc751527e584d2c0356f10b1bb807`（I03再レビュー済み）。**I04のlocal実装・実proof/SBF統合検証を完了。次の実装はI05 Postgres ledger・quote・signer。** 実wallet端末・公開cluster/RPC・hosted CI・G1〜G4公開gateは未合格。

## 実装

- Anchor Vaultにcreate/append/seal/closeを追加。最終長を確保したlayout 2 buffer、正確なoffset、digest、uploader署名、保存rent payer、期限、PDA/pool/profileを検査。execute成功時のcloseと失敗時rollbackは既存handlerを使う。appendのVec長はAnchorのdecode前に制限し、末尾余分byteも拒否。
- SDKは全5操作のv0 bufferとinline finalize、任意署名者による期限後closeを生成。fee payer / instruction payer / uploader / token owner / rent payerを分離可能。全署名を含む実serializeからappend量を決める。v0対応を明示したwalletだけを使い、全Ed25519署名・message不変を検査する。v1はadvertiseしない。
- 送信前にpayload・digest・buffer・expected root/ID・snapshot・署名済みbytes・blockhash/lastValidBlockHeightをdurable journalへ保存。finalized receiptでmessageを照合し、未知のexecute/finalize/closeを新署名で自動再送しない。uploadの期限切れはfinalized prefixを照合した場合のみ再開。account不在を成功扱いしない。
- indexerはfinalized成功transactionを実行順でreplayし、CPIと祖先の成功を検査する。全ログ欠落時には成功したinline/buffer命令履歴から復元。bufferのclose/reuseは作成位置で世代を分離する。元Poseidon 32段tree、sequence、Active/Pending、old-root保持、finalizeのroot不変を再構築する。
- HTTP root/path/zero-path/snapshotを追加。実accountとの同slot照合が終わるまで配信しない。JCS snapshotはhashだけで信用せず、同cutの信頼済みreplayと全Active/Pendingを照合する。
- 15命令の生成IDL、account順序・権限・固定wire検査、再現scriptとCI transport jobを追加。macOS arm64のSBF toolchain archive hashも固定した。

SBF試験は全5操作のuploadから実proof executeまで、独立rent payer、offset復旧、封印後変更拒否、期限等号、旧digestでPDA再利用、別buffer同payload、stale root、Token CPI rollbackを含む。SDKの4シナリオはclose/challenge/finalize/expiry。命令数・event列・最終root/status・USDC整数残高を固定assertし、generatorが空/途中でも自己一致で通過しない。

各scenarioでVault emit後に後続System命令を失敗させ、ログだけ残った取引をindexerが無視することを確認。別のCPIテストではVault成功後に祖先が失敗してouterがcatchする場合も除外する。レビュー中に見つかった空append・不正payloadのsealについては、chainが受理する成功履歴をindexerも受理するよう修正した。

RPC/runtimeテストは実SBFのPool/Tree/Active/Pendingの生bytesをlocal HTTP fixtureから配信。owner、discriminator、bump、profile、status、長さ、block anchorの22種改変と、複数batchのslotずれを拒否する。これは公開RPCへの接続試験ではない。

## 限界と後続gate

元回路・Poseidon・proof fixtures・VK・root Cargo.lock・circuit profileは変更していない。indexerは独立workspace/lockを使う。通常ELF SHA-256は `f8e57adeee417ca58c27324999d3e46013800fd7d8892880ea8ee1becefc2334`。鍵は公開test entropy、mintはlocal 6 decimals SPL tokenであり、live Circle USDC・production setupではない。G1のlocal CU/サイズ目標は満たすが、target cluster・wallet・全機能E2Eを未確認のままG1合格とはしない。

walletは標準的なv0 adapter契約と実Ed25519署名を検証した。実端末UI・公開RPC finality・provider・v1は未検証。復旧RPCの障害注入はsimulated。暗号化durable storage実装と利用者note journalはI08で統合する。npm auditは間接依存由来moderate 4件、high/critical 0件（到達性の整理はSDK README、release前の解消/評価が必要）。

indexerはinitializeからのarchive replayを採用し、再起動時の高速な認証済みcheckpointは未実装。全account batchに同じfinalized slotを要求するため、標準RPCのcutが進む場合は配信停止して再追従する。大規模live運用の可用性/SLOは未実測。Agave v2.2.0の[block metadata実装](https://github.com/anza-xyz/agave/blob/v2.2.0/rpc/src/block_meta_service.rs)がClock時刻をblockTimeへ保存する前提を使い、時刻不在時は停止する。blockhash/slotの信頼は設定したarchive RPCが境界となる。

I03の既存evidenceは上書きせず、新ELFの回帰結果を別directoryへ保存した。hosted CIは今回未実行。G2のledger/sign-once、G3の実provider、G4のsetup/監査/復旧演習は後続作業として残す。
