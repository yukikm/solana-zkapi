# I08 — SDK/WASM/wallet/Go clientd local受入

2026-10-04 JST。**I08 A〜Fのlocal実装・受入を完了**。既存の暗号化journal・`ControlClient`・I04 v0 transportへ接続し、browserとGo clientdで認可・会計状態機械を共有する。実provider、実wallet端末/公開RPC、実Tor、他OS、production署名配布、hosted CI、G1〜G4の合格は含まない。I10への完了引継ぎは宣言しない。

## 今回完成した実装

- `apps/clientd/prover/`とSDK prover bridge：元RP/WP/treeをnativeと実WASM workerで生成し、共通検証器で検証。検証済manifest/artifactだけを読み、worker失敗時のnative代替は明示的に設定する。
- `wallet.ts` / `wallet-chain.ts` / `wallet-standard.ts`：完全なnote witnessとwallet操作を暗号保存。finalized入金、clearanceのexact-N復旧と署名検証、合意出金、escape/finalize、stale-root再prove、送信前の署名bytes永続化を実装。clearanceが取得不能な場合は、未署名操作だけを同じN/出金先のescapeへ明示切替できる。
- `apps/clientd/cmd/`・`internal/`・`runtime.ts`：Go loopback APIと同じSDK lifecycleをprivate Unix socketで接続。Host/Origin/peer検査、推論/admin credential分離、明示mode、4 API/count_tokens/SSE、default 60秒/0秒key reuse、終了時close、切断時cancel、再起動照合、wallet管理APIを実装。直接推論も送信前journalへ記録し、未知の推論を再送しない。
- `secret-custody.ts`：ランダムjournal keyをscrypt＋AES-GCMでpassphrase保護し、秘密をstdinで受け取る。SOCKS5 remote DNSとfail-closed relayをcontrol/provider/indexer/RPC全経路へ適用。配布manifestを独立hash pinし、Node/runtime/native binary/依存の全file hashと権限を確認する。OS keychain統合・productionコード署名とは区別する。
- `control.ts`：精算済みsessionで認証付き照会が404となる未受理operationの明示照合を追加。全明細と後継署名を再検証してからcommitし、不明な推論を再実行しない。

Node 24.19.0で発見したprocess lockのGC解放を修正し、SQLite connectionをlock解放までmoduleから保持する。強制GC・SIGKILL・競合processで回帰した。レビューで実HTTP切断時のstream cancel待機、終了時の実行中request待機、key reuse 0時のserver TTL、clearance停止からのescape切替も修正した。

再起動時にcontrolが停止している場合や精算の明示照合が必要な場合は、`recovery_required`のまま管理APIを維持し、推論を停止する。明示的なrecover/close/reconcileで旧sessionが解決してから再開する。送信前の認可が期限切れになった場合は、既存`cancelUnsent`へ接続した`/admin/cancel-unsent`を使う。送信済みか不明な認可のcancelは拒否する。journal破損、trust/custody/chain不一致、検証binaryのhash/権限不正は起動時に停止する。これらを再起動・HTTP管理API・権限分離の回帰に追加した。
