# OpenRouter lifecycle fixture follows one-sample retirement

The `i10_e2e` stage in [implementation run 37865537882](https://github.com/yukikm/solana-zkapi/actions/runs/37865537882/job/113611252562) at `77004930a5eb4a2ab991b35441d211a43602eab5` failed after 67.42 seconds. The earlier [Rust fault-fixture correction](PD-openrouter-retirement-fixture-ci-20261009.md) passed in that job, exposing the next obsolete expectation: the TypeScript fixture required two OpenRouter usage reads before deletion. The implemented Ethereum-style policy retires after one successful sample following the grace period. Its correct first read therefore triggered the fixture's `1 !== 2` assertion and HTTP 500, leaving the direct session draining. The unchanged local source reproduced the same failure in 39.13 seconds.

The change adjusts **two test assertions only** in `packages/sdk/test/i10-e2e.ts`: the DELETE prerequisite and final usage counter each change from two to one. Deletion still requires a disabled key, exactly one successful usage read and exactly one deletion. Inference counts, signed-receipt validation, balance conservation and runtime behavior remain unchanged.

The first corrected local run passed typechecking but stopped before any mode lifecycle with `signer readiness timeout` after 2.98 seconds. A read-only audit found that the existing approximately two-second socket startup window expired; the cause remains unproven. Its log, result and audit are preserved. The existing runner cleaned ephemeral signer/PostgreSQL state and did not retain the child's PID or final exit status. No startup deadline, harness behavior or source changed for one explicitly selected local retry, which **passed one test with zero failures or ignored cases in 40.04 seconds**.

That passing local scope exercised **28 API cases**, including four interrupted responses, across five mode/provider combinations. It verified 29 signed receipts, six settlements and 19 actual Vault SBF transactions. The same note conserved the fixture balance: 5,000,000 micro-USDC deposited, eight charged and 4,999,992 withdrawn. OpenRouter create, disable, successful usage read and deletion each occurred once; inference replay remained zero. Observed maxima were 1,232 bytes per transaction and 434,334 CU. The escape/challenge race used actual SBF with an SDK challenger plan; the challenger daemon was not joined in this test.

The test used Node 24.19.0, a fresh private PostgreSQL 18.6 instance with durability enabled, retained native proof tools/Vault SBF and the preexisting manifest-matching IDL fixture override. Hosted CI uses PostgreSQL 16; this local result does not stand in for a corrected-source hosted result. Original output reports were restored byte-for-byte and guarded inputs stayed unchanged. The [JSON evidence](PD-openrouter-e2e-fixture-ci-20261009.json) pins the original failure, startup failure, explicit retry and source diff.

This test-only correction changes no installed service or Linux binary, sends no public provider request or public-chain transaction, and establishes no new full-workflow, public-readiness or release-gate pass. Source publication and subsequent hosted results are separate checkpoints.
