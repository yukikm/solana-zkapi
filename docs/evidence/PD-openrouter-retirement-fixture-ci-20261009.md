# OpenRouter retirement: I10 fault fixture correction

The first hosted workflow after the [Ethereum-aligned OpenRouter retirement change](PD-openrouter-ethereum-parity.md) exposed an outdated integration-test expectation. [Run 37860649898](https://github.com/yukikm/solana-zkapi/actions/runs/37860649898) at exact source `ec640fa77ad7253b8f7bb4b4975434bba80063f9` completed with eight jobs successful and `client-challenger` failed. Its I10 aggregate passed backend, SDK, challenger, wallet, clientd and operations stages. Integration load then passed **768 completed operations, 769 receipts and 34 invariant snapshots**, before `i10_faults` failed with `dispatcher response lost`. The following `i10_e2e` suite and offline-provider workflow stage did not execute.

The original test still expected the first successful management usage sample to return no finalization. The published runtime already selects one sample after the configured retirement grace, persists it and then attempts deletion, matching the requested upstream policy. The fixture deliberately loses the first DELETE acknowledgement. Its obsolete `await?` therefore propagated the child's EOF error at that earlier point. This is a deterministic fixture mismatch: the unchanged test reproduced the same error locally before the correction. The original hosted failure, local reproduction, earlier results and in-progress CI observations remain preserved.

Only [the I10 fault fixture](../../services/control/tests/i10_faults.rs) changes. It now expects that deliberate DELETE failure immediately after the first successful usage sample. It also checks that the selected usage is durable before deletion, the historical extra observation is absent, and the complete retirement checkpoint remains identical across a writer restart. Exact provider counters require one create, two list pages, two disables, two usage reads (one failure and one success), and two delete attempts after recovery. The original failure injection, immutable dispatch claims, receipt equality, capped accounting and no-replay checks remain in place. No production source changes.

The corrected exact test passed on fresh disposable **PostgreSQL 18.6** with `fsync`, `full_page_writes` and `synchronous_commit` enabled, using a private Unix socket with TCP disabled. It exercised **12 proxy faults, four direct recovery lifecycles, four healthy capped operations, 11 writer-backend losses, 20 durable claims and 24 signed receipts**. All three invariant counters and automatic inference replays were zero. Both disposable clusters were stopped. This local PostgreSQL version is distinct from hosted PostgreSQL 16.

That source still contains the old fixture. This record does not predict its final outcome or claim hosted success for the corrected fixture.
