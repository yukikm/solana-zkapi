# Durable replay checkpoints: installed successor

The writer and archive-backed indexer now have the private restart-checkpoint implementation installed. A valid checkpoint restores the accepted replay prefix and processes its suffix; a missing, incompatible or damaged checkpoint takes the original full validation/replay path. The exact Linux binary was installed and both services started at 18:19 UTC. This establishes deployment, **not measured live restart speed or current public readiness**. The [JSON report](PD-restart-checkpoints.json) pins the retained logs and source observation.

The complete Indexer state includes active and pending notes, tree inputs, payload buffers and their creation positions, spent nullifiers, configuration, transition ordering and accepted-block digests. The Scanner also retains exact Pending generations and historical time. Current jobs, signed bytes, unknown outcomes and transport records always come from the authoritative journal, never the disposable cache. Restored readiness is false until the existing fresh finalized account reconciliation succeeds.

The cache binds its configuration domain, saved state digest and exact archive slot/hash/time. Owner-only files are atomically replaced after fsync; retained files must preserve their checked Unix identity, and the anchor chunk and new suffix are authenticated. Checksums and filesystem continuity are a protected-local-storage trust model, not a cryptographic proof of chain-derived state. The runtime payload is bounded to 256 MiB and archive metadata to 64 MiB. Ordinary JSON files up to 32 MiB use bounded capture plus the same strict decoder/hash checks; larger files retain the streaming parser. No archive pruning or financial-history rewrite is introduced.
